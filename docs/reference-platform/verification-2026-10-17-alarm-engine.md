## 已执行的闭环

规则启用 → 后台读取既有EMS真实采样 → 条件连续命中 → 创建 `source=rule` 告警 → 保存采样证据/规则快照/系统处理记录 → 正常采样连续达到恢复时长 → 更新自动恢复时间、告警版本和系统处理记录。

- 只读查询既有 `ems_observation_final`，不写ClickHouse、不启动共享消费者、不向设备下发。
- 支持设备即时数值的原值比较和区间，按本设备测点代码或EMS协议ID唯一映射，单位一致；多条件AND，连续周期须一致。
- 检测采用UTC完整一分钟桶的末次可信源时间采样，连续周期为连续完整分钟；桶结束后留5秒接收时间。采样/接收超过180秒、无效、未来、冲突、无绑定或单位不符均不触发、不恢复，并记录原因。
- 恢复时长使用实际采样源时间；首正常帧取全部条件采样的最晚时间，后续取最早时间作为保守证据前沿。相邻分钟但只差2秒的样本不能算已正常60秒。缺样、断档、越出UTC时段会打断累计。
- PG保存执行游标、锁存及正常起点。行锁和活动事件唯一约束保证并发/重复调度/重启不重复报警。人工关闭后，持续异常保持抑制，需先正常再异常才能重新触发。
- 规则改版或绑定变化时，不用新条件/新绑定自动恢复旧事件；提示先人工处理旧告警。
- 后台使用最近修改者当前有效的Web端 `alarm.read`、`alarm.handle`、`telemetry.read` 授权；查询前后重验。原始采样证据另需当前读取人的 `telemetry.read`，告警阅读权限不因此扩张。
- 系统处理记录使用 `actor_type=engine`，显示“系统检测”，不冒充人工确认。规则告警保存原始站点归属，设备迁移不改变历史授权。
