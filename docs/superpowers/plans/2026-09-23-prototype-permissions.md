# 原型角色与组织权限补齐 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按已实际核实的三种登录身份与安装服务商权限配置流程，补齐角色定义、成员逐条授权和组织管理，并保持原型布局。

**Architecture:** PostgreSQL 存储角色、操作权限、成员授权和有效期，后端统一鉴权；React 页面呈现相同授权模型。角色的操作权限与授权的站点范围必须在同一条授权关系内联合判断，不能对全部角色和全部站点分别求并集后放行。

**Tech Stack:** 现有 Java 21 / Spring Boot / JDBC / PostgreSQL、React / TypeScript / Vite。迁移沿用 `database/apply.sql` 和 `schema_migration`，不启用 Flyway。此项不新增框架，不改变 ClickHouse 遥测结构。

**Spec:** 本文“原型依据与范围”为本计划的需求基线，依据用户本次要求和对静态原型的浏览器核实；原型路径 `前端静态原型/Enerlution-cloud-deploy-20260919-v2`，地址 `http://127.0.0.1:62462/`。

## 全局约束

- “严格按照数据库三范式建表，不建非必要字段。”
- 只使用新业务库 `ems_cloud_v2_proto`；不读写旧业务库以完成迁移。
- 保持原型布局、样式和关键操作流程；无数据保留结构，不能用演示数据填充业务页面。
- 暂不实现新站接入流程、EMS 接入、真实策略下发、外部市场交易、真实固件升级。
- 三个登录身份是演示工作台入口，不等于业务角色全集；真实权限由后端返回。
- 用户已要求在上传基线后开始实施；代码在独立分支修改，数据库先做回滚演练，正式切换前停旧服务并重新备份。
- 原型中尚无实际后端能力的权限项仍保留展示，明确标记暂不可用，不能勾选后声称功能已经实现。
- 不按本计划自动给线上成员扩大权限；配置能力的初始化与普通成员原授权迁移分开处理。

## 原型依据与范围

### 三个登录身份

| 身份 | 一级菜单 | 特征 |
| --- | --- | --- |
| 电站业主 | 总览、资产与站点、运营中心、分析与报告、设置 | 站点收益、收益结算/证据链、运营报告和收益报告；无资产编辑入口 |
| 运维人员 | 总览、资产与站点、运维中心、工单与审批、分析与报告、设置 | 运维总览、告警处置、设备健康、固件、工单/巡检；设备健康报告 |
| 安装服务商 | 总览、资产与站点、运维中心、工单与审批、平台管理、设置 | 站点编辑、运行策略、电价设置，以及成员/组织/角色权限管理 |

### 安装服务商角色配置

入口：平台管理 → 角色权限。左侧角色列表，右侧分组权限矩阵，底部取消/保存。

八类默认业务角色：项目业主/资产方、项目管理方/项目公司、EMS运行管理方、运维服务方、EPC/系统集成方、设备厂家、平台治理方、只读观察员。

六组共 38 项原型权限：

| 模块 | 操作项 |
| --- | --- |
| 资产与站点（8） | 查看站点与设备、新建站点、编辑站点、删除站点、查看运营收益、查看运行策略、编辑运行策略、下发运行策略 |
| 运营中心（6） | 查看运营总览、查看收益核算、查看计划调度、制定调度计划、查看响应邀约、接受响应邀约 |
| 运维中心（6） | 查看告警、查看设备健康、处理告警、转为运维工单、上传目标固件、执行固件升级 |
| 工单与审批（6） | 查看工单、新建工单、编辑工单、处理工单、查看审批、审批申请 |
| 分析与报告（4） | 实时数据分析、历史趋势分析、生成报告、下载数据 |
| 平台管理（8） | 查看客户、管理客户、查看组织与成员、管理组织、管理成员、配置角色权限、分配成员权限、查看安全审计 |

角色新增包含名称、说明；新角色初始无权限。使用中的角色禁止删除，不能级联撤销成员授权。取消修改恢复已保存勾选；切换角色时应提示未保存变更，避免静默丢失。

### 成员授权与组织

成员列表 → 查看权限 → 已分配权限列表 → 分配权限。每条授权独立包含一个角色、一组站点、有效期；期限有长期、30天、90天、1年。列表显示角色、适用站点、授权来源、有效期，并能编辑、移除和查看完整角色权限。

成员资料包含姓名、账号、邮箱、所属组织、状态；组织包含名称、上级、负责人，支持新增子组织、添加已有成员和移出组织。移出组织与撤销授权是两个动作，不可混用。

当前三个演示账号未展示独立客户管理菜单；矩阵存在查看/管理客户权限。客户管理沿用当前已实现功能并接入独立权限，不据此擅自增加客户接入、套餐和计费业务。
