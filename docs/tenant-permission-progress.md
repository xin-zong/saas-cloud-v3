## 实施结果

T01—T10 的本地实施范围已完成：数据结构与预检、能力计算、会话/激活、企业申请与审批、菜单/权限包/预制角色、企业/员工/角色/站点授权、01—08 业务资源和出口校验、服务端菜单导航、管理页面、旧模型清理及迁移恢复演练。原计划按职责列出的多个 controller 合并为轻量 TenantGovernanceController / PermissionConfigurationController；验证用例由单元测试、原生 PostgreSQL 脚本和真实 HTTP 流程共同覆盖，不依赖同名占位测试。

核心规则：企业隔离；企业管理员覆盖本企业未来站点；预制模板实时引用；Web/App 独立；角色权限和站点集合在同条授权内组合；普通管理者不能扩大自身权限、站点或有效期，不能通过改共享角色间接扩大能力。旧客户/组织表与旧继承视图已删除，旧接口返回 410。

迁移版本：V19 schema、V20 capability views、V21 lifecycle guards、V22 people metadata、V23 legacy removal、V24 contracts/templates、V25 menu leaf/reference guards。迁移工具备份后按版本事务执行，拒绝重放种子。

用户确认的映射：原三个站点及普通账号归演示企业；superadmin 归平台，owner 为受保护企业管理员，operator 为 Engineer，integrator 为 Admin。新增 Platform Admin、Approval Manager、Support Agent、Installer、Viewer 覆盖账号。原四账号的密码与 MFA 指纹核对未变。
