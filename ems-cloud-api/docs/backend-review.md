### New actionable findings

1. **[P1] Operations CSV bypasses strategy permissions.** `src/main/java/com/enerlution/ems/business/ReportController.java:19` exports `operating_plan` and `plan_period` after `asset.read`, while the normal plans endpoint requires `strategy.read`. The default owner has `asset.read` and `report.export` but no `strategy.read`, so can retrieve another functional domain's drafts, statuses and target power through the export endpoint. Require `strategy.read` on this branch. Verify a station-authorized owner receives 403 and a suitably authorized operator can export. Station scope itself is checked correctly.

2. **[P2] CSV formula neutralization fails on multiline values.** `ReportController.java:25` uses whole-string `String.matches` with `.*`; Java dot excludes line terminators. A station name such as `=SUM(1,\n2)` is accepted by the station edit validation and reaches the operations CSV without the protective apostrophe. Local Java 21 JShell evaluation of that exact prefix check returned `false`. Inspect the first character directly (and account for leading control characters) instead of requiring the whole string to match; retain proper CSV quoting. Add a multiline regression. This reviewer verified the Java bypass, not spreadsheet application execution.

3. **[P2] Market capacity check sums reservations that are never concurrent.** `src/main/java/com/enerlution/ems/business/MarketController.java:21` sums every allocation overlapping any part of the proposed interval. On a 100 kW station, existing 00:00–01:00 at 60 kW and 01:00–02:00 at 60 kW incorrectly prevent a new 00:00–02:00 at 40 kW: current code adds 60+60+40, although actual peak is 100. Compute maximum simultaneous occupied capacity over interval boundaries under the existing station lock; test this adjacent-interval case plus a genuinely excessive overlap.

4. **[P2] Station edits can invalidate new market-capacity invariants.** `src/main/java/com/enerlution/ems/business/AssetController.java:24` checks only plan periods before reducing rated power. Create an 80 kW market draft on a 100 kW station with no conflicting plan, then edit the station to 50 kW: the edit succeeds and leaves a reservation over its limit. Validate relevant market commitments against the proposed rating under the station lock, using the same peak-overlap rule as draft creation. This is now reachable through two implemented APIs, not merely an unchecked direct SQL import.

The operations-export permission bypass is a material blocker before exposing this API as permission-complete. The other three findings should be fixed before claiming export sanitization and market-capacity validation complete. No additional definite member-management privilege escalation was found in the reviewed synchronous flow: organization membership is checked, self grant changes are denied, and requested station/role permissions must be possessed by the caller.

## Actionable findings

1. **[P1] New-database restriction is absent from the API and constraint test entry point.** `src/main/resources/application.yml:12` accepts any `EMS_DB_URL`; no Java startup check verifies `current_database()`. Thus an accidental old database URL with compatible tables and write privileges allows all business mutation endpoints to modify it, despite the explicit new-databases-only instruction. `database/tests/constraints.sql:2` also begins writes without the guard used correctly by `database/apply.sql:2`; rolling back does not undo identity sequence increments. Add a fail-closed database identity check before serving requests and before test SQL writes. Do not test this against an old database: use a mock or a newly created disposable wrong-name database.

2. **[P2] Missing required query parameters become HTTP 500.** `src/main/java/com/enerlution/ems/common/ApiExceptionHandler.java:29` catches framework exceptions generically, while its 400 handler at line 22 omits `MissingServletRequestParameterException`. For example an authenticated `GET /api/stations/{id}/plans` without `date`, or history without `from`, raises this framework exception and returns 500 instead of the required 400. Map missing parameters explicitly and verify with MockMvc. Unsupported methods similarly fall through to 500 rather than 405.

3. **[P2] Null list elements produce HTTP 500 in validly parsed requests.** `src/main/java/com/enerlution/ems/business/OperationsController.java:17` only requires a non-null periods list; `BusinessRules.java:18` dereferences every member. A plan with `"periods":[null]` passes validation and throws NPE. The tariff list at `OperationsController.java:34` has `@Valid` but no element `@NotNull`, so its sorting/loop has the same problem. Require non-null elements and return 400; verify both endpoints, not merely `assertThrows(RuntimeException.class)` on the helper.

4. **[P2] Completed inspections can have a NULL result in PostgreSQL.** `src/main/resources/db/migration/V2__maintenance_operations.sql:30` uses `CHECK(status<>'completed' OR btrim(result)<>'')`. With completed status and NULL result, that expression is UNKNOWN and PostgreSQL accepts it. A completed row with a timestamp but no result therefore passes both checks. Use an explicit `result IS NOT NULL` clause for completed rows. The current API requires a note, so this is a database integrity defect affecting SQL imports/other writers, not a demonstrated bypass of that endpoint.

5. **[P2] Audit reads bypass station scope through same-organization actors.** `src/main/java/com/enerlution/ems/business/SettingsController.java:20` restricts events only by the actor's current organization. A user explicitly granted `audit.read` and station A can therefore retrieve events about station B whenever the actor shares their organization. Other business queries require the viewer's station grant. `DomainSupport.java:20` stores only free-text business references, preventing reliable relational filtering. Give events a structured authorized subject association, or another explicitly defined visibility scope, and test two users in one organization with disjoint station grants. No default role has `audit.read`, so this becomes reachable after an explicit grant.

## Additional semantic/coverage gaps

- `RevenueController.java:17` returns all `settlement_payment` rows, including future `paid_on` dates, although the parent settlement recognition date is capped at today. If consumers treat these entries as actual received payments, current cash totals can include future values. Either filter actual payments by the agreed as-of date or distinguish scheduled entries explicitly. No aggregate endpoint was present in the reviewed snapshot, so an incorrect total is not asserted as already observed.
- Authentication paths do not insert security audit events. Login success/failure, MFA verification and logout will not appear in `/audit`. Decide and implement the required security-event contract without logging passwords, tokens, OTP values or encrypted secrets.
- The schema's junction tables, measurement-point/device relationship, separated currency contract, and typed approval FKs are consistent with the stated normalization direction; no definite 3NF violation was found. The requested per-table candidate-key/field-semantics inventory is not supplied by DDL alone. Cross-table invariants such as same-station topology links and work-order/alarm links are not enforced by the current FK structure. The API checks the latter on creation; do not claim database-wide enforcement for imports.
- Plan creation and station power edits both lock the station row, and work-order/approval transitions lock their state rows in transactions. These are useful concurrency controls, but existing sequential tests do not demonstrate concurrent correctness. Test simultaneous plan versions, accept/complete requests, approval decisions, hierarchy reparenting and grant revocation against the new PostgreSQL database.
- ClickHouse `FINAL` deduplicates by `(point_id,sampled_at)` before averages; the revision contract is documented. Existing integration script checks empty history only. Verify duplicate revisions/corrections, non-empty bucket values, interval boundaries and future samples. A write-time guarantee that corrections have increasing revisions remains the controlled importer’s responsibility.
