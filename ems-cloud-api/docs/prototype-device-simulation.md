# 两站点设备模拟数据

范围仅为新库 `ems_cloud_v2_proto` 和 `ems_cloud_v2_proto_telemetry`，站点 `PROTO-001`（ID 4）、`PROTO-002`（ID 5）。未修改旧库、表结构、账户或授权。

每站 13 台设备：PCS ×2、BMS ×1、电池簇 ×2、并网电表 ×1、负荷电表 ×1、消防控制器 ×1、温控系统 ×1、光伏逆变器 ×1、光伏 DC/DC ×1、电网接入 ×1、园区负载 ×1。覆盖现有 8 个设备分类；DC/DC、电网与负载使用现有 OTHER 分类，以型号和名称区分。

每站包含 129 个测点、13 条拓扑连接、15 条明确标识的模拟告警（13 条已恢复、2 条活动）、13 条 SIM 固件历史记录，以及通信状态、健康度、型号、序列号。两台原型 PCS 复用原记录及原功率测点；既有告警保留。新增名称带 `[模拟]`，型号、序列号和固件带 `SIM`，不代表真实设备部署或升级。

历史范围：2026-08-27 10:20 至 2026-09-26 10:20（北京时间），5 分钟间隔，每测点 8,641 条，两站共 2,229,378 条逻辑采样。负荷、光伏、储能与电网功率保持功率平衡；模拟 SOC 在 30%–70% 内，日充放电量平衡。温度、电压、电流、三相电压、绝缘、电芯温差、循环次数、CO/H₂、消防和温控相关测点均有历史数据。

## 导入与验证

脚本：`database/seed_prototype_devices.py`。在数据库主机以 root 执行 `python3 seed_prototype_devices.py`；PostgreSQL 使用 peer 身份认证，ClickHouse 使用现有受管配置，不含明文凭据。

每次先备份新业务库和两站现有遥测到 `/var/backups/ems-cloud-v2-proto/sim-devices-<UTC时间>/`，目录权限限制为当前用户。首次写入前备份：`sim-devices-20260926T022033361243Z`；补齐测点前备份：`sim-devices-20260926T022324926510Z`。各目录含 `postgres.dump`、`telemetry.native` 和导入 `report.json`。

设备/测点/拓扑按自然唯一键复用；发现非模拟厂家设备占用同一编码会中止。重复历史键由 ClickHouse ReplacingMergeTree 的 revision 与 FINAL 查询去重。复跑补齐测点后仍为每站 13 台设备，没有重复创建设备。导入在 PostgreSQL 事务内执行；若 ClickHouse 导入失败，关系数据保留，可修复错误后复跑，不删除已有业务数据。

生成器校验通过：34,272 个跨全天代表样本有限值、SOC 范围、日充放电量平衡。数据库校验：258 个测点、2,229,378 条逻辑采样、无非有限数值。

## 边界

这是一次性入库数据，不是后台持续采集服务；API 会按既有规则在观测超过 15 分钟后显示离线。脚本复跑可更新近期历史和观测时间，不添加定时任务。

现有设备接口尚未提供的通信配置、投运日期、额定参数和操作日志字段，没有为填满页面而新增自由 JSON 或冗余字段；这些前端区域仍需后续接口接入。数据库已有遥测通过历史接口读取，设备实时卡片的前端映射也需要独立接入。未生成真实收益、付款、EMS 下发或设备执行结果。

真实 API 验证通过：使用现有安装服务商账号登录后，分别读取两站设备、测点、拓扑、告警和固件记录；逐站检查 9 条主曲线近一天数据，每条返回 287 条样本（窗口随着校验时间滚动）。验证后退出此次会话，未修改账户、权限或执行设备操作。
