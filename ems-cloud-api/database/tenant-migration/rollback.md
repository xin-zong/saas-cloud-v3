# 回退与恢复

新版本删除客户/组织实体，不能用反向 ALTER 假装恢复旧数据。必须恢复切换前 PostgreSQL 备份，并成套使用旧前后端和 EMS 入库配置。

1. 记录迁移报告中的备份绝对路径、源提交、前后端包摘要、运行环境和数据库名。备份包含账户哈希，权限保持 0600，不上传 Git。
2. 停止新 API 和向目标 PostgreSQL 写入的 EMS 入库服务。保留切换后数据库用于核对，不覆盖或删除。
3. 优先把切换前 dump 恢复到另一个明确命名的新库，验证完整性后再改服务数据库指向。不得恢复到用户早期业务库，也不得对运行中的库执行覆盖恢复。
4. 使用匹配的旧 API、旧前端、旧入库配置一起恢复服务；会话保存在内存，用户需要重新登录。
5. 核对账号 ID/密码哈希指纹/MFA 行、电站/设备/测点/EMS 绑定/合同 ID、负责人、遥测映射和 ClickHouse 历史关联。
6. 备份后的新业务写入不能自动合并进旧模型；切换失败时应保持维护状态，核对事件后制定迁回方案，不能丢弃这些写入。

2026-10-14 演练：从 `ems_cloud_saas_final_test` 的迁移前备份恢复到独立 `ems_cloud_saas_restore_test`；恢复旧 customer/organization 模型，原四账号密码指纹和 3 电站、39 设备、556 测点、1 EMS 绑定 ID 与原源库一致。未修改原库，未执行正式云端切换。
